## 为什么是 vscode ？

说到AI agent，想必多数人脑子里的画面应该是这样的（实拍，请忽略侧边栏内容...）：

![GPT网页版](/Dr_xiaoma-Blog/images/claude-code-vscode-setup/GPT网页版.png)

嗯，虽然笔者不是反对这样的chatbot（聊天机器人）形式，实际上，无论是OpenAI（GPT母公司）还是Anthropic（Claude Code母公司）都看到了网页版的巨大商业价值，都在全力推动网页版的更新和订阅制收费，现在的网页版也早已跳脱简单的chatbot，RAG注入外部文件、项目规划、深度思考、Plan Mode、直接调用生图功能...可以说已经集成了很多实用功能，在笔者看来，也是AI agent发展到最后的最终形式——一个简明清晰、功能完善的可视化交互页面

但是问题在于目前这种可视化页面**并不完善**。

你不能手动地整理项目文件，你不能查看agent运行时的沙箱流程，你不能及时获取到最新的功能和社区强大的插件...

最糟糕的是，你极有可能面对一些厂商的"欺诈"。相信你一定在网上听说过"满血版"这一极具网游色彩的比喻，人们用是否满血来评价一个模型提供商是否诚实地向他的用户提供了最优的模型和足够的思考链，烧了足量的token来做出回答。然而，网页版通常是完全免费或者采用订阅版计费，厂商无法有效地控制token支出来盈利，所以当你使用网页版时——笔者不想过于恶意地揣测——**有不小的可能**使用了厂商给出的"阉割版"模型，如果你曾尝试过API和网页版，或许可以对比一下同样的模型是否在生成时有显著的差距

所以，作为一位严谨、追求进步的学者，你应该选择更有效、更可控的方案，*基于CLI部署AI agent*

而 **vscode** 作为工科生最常使用的编辑器，自然是承担这一任务的首选（至于cursor，本质换皮，笔者未使用过），具体实现效果如下图：

![vscodeCLI](/Dr_xiaoma-Blog/images/claude-code-vscode-setup/vscodeCLI.png)

对于生活工作中不常面对代码的学生，这样的界面看起来非常吓人，但是这确实是实际工作最高效的组织形式，你可以通过左边栏的项目文件管理器组织你的项目文件，增删查改都很方便且很直观，配合AI agent，你能清晰地看到它生成了什么新文件，改动了什么文件，并通过git版本管理方便地保留/抛弃更改。最重要的是，右侧的CLI版本的agent可以**直接**查看你工作区的项目文件并且在你的指令下做增删改动或者运行bash指令，这一动作会**直接**体现到左边的项目文件上，而不需要你充当AI的搬运工，从网页版的对话回答中复制一大段到项目中，报错了还得将报错信息复制给AI（笔者相信即使在agent发展迅速的当下仍有很多人坚持这种搬运）。vscode的使用方法笔者不再赘述，网上教程很多

## 为什么是Claude code/Codex插件？

这个问题得拆开说，首先是关于agent框架，笔者最推荐的就是**Claude Code**，事实上，这一agent生态在一众工作者看来评价都得给到夯。优秀的Harness、活跃的plugin/skill社区、占主流的用户数量都是Claude Code备受青睐的原因，自然，笔者在充分体验Claude Code和Codex框架之后，仍然更推荐Claude Code。至于除了这两种框架之外是否有更好的选择（或者自己搭建），笔者未尝试过，不能妄言

这时候可能就有同学要问了：*唉upup，你这也是搞AI的，怎么就用这些国外的模型呢，连deepseek也没用过吗？*

这就得提到agent框架和实际搭载的内核模型的区别了，直接看看deepseek v4的回答：

> Q: 讲一下Claude Code CLI框架和实际使用的Claude Code模型的区别
>
> Answer generated by Deepseek v4:
>
> ### ⚙️ Claude Code CLI：一个为AI设计的"操作系统"
>
> Claude Code CLI的强大不在于"模型本身"，而在于其作为"AI代理运行时"的精密设计。
>
> - **核心是智能代理**：与 Copilot 的"副驾驶"或 Cursor 的"增强版编辑器"定位不同，Claude Code的定位是"**自主编码代理**"。它能自主规划并执行跨文件修改、运行测试、修复Bug等多步骤任务。
> - **精妙的工程架构**：
>   - **QueryEngine (查询引擎)**：这是框架的"大脑中枢"，拥有约**4.6万**行代码。它负责与模型API通信、管理工具调用循环和API Token，以及处理历史对话。当上下文窗口满时，框架的`/compact`命令能智能压缩对话，这在第三方通用客户端中难以实现。
>   - **复杂的工具系统**：框架将文件编辑、Bash命令、Git操作、代码搜索能力封装成了约**40个**不同的"工具"，供模型调用执行。
>   - **严谨的权限模型**：为防止AI误操作，安全至关重要。Claude Code设计了一套三级权限模型：**Allow/Ask/Deny**，确保任何写操作或耗时命令在执行前都必须经过你显式确认。
>   - **丰富的扩展生态**：你还可以通过**命令（Command）**、**可复用技能（Skills）**、**子代理（Subagents）**和**生命周期钩子（Hooks）**等上层建筑，按需扩展CLI的能力。
>
> ### 🧠 Claude Code模型：为编程任务深度优化的"大脑"
>
> 它的能力远不止于"懂代码"，而是为AI代理的特定需求做了深度优化。
>
> - **深度优化的编程专长**：Claude模型本身在编程、逻辑推理等方面就达到了**行业顶尖水平**。在Claude Code中，Anthropic很可能使用了特定指令或微调版本，以适配代理的工作需求。
> - **针对性功能的依赖**：Claude Code中的许多独特功能，并非通用API能实现，而是深度依赖Claude模型的独家特性。例如：
>   - 智能**上下文压缩（Context Compaction）** 能力依赖模型内部独特的摘要机制。
>   - **深度推理模式**和**思考签名**等技术依赖模型的高级参数支持。
>   - **100万token的超大上下文窗口**也是Claude Opus 4.6模型的"独门绝技"。
>
> > 这也解释了为什么虽然能通过代理网关接入GPT等其他模型，但往往无法达到原生Claude模型的完整效果和稳定性。

笔者只是在推荐Claude code的CLI框架而非推荐其模型，模型的优劣有各种指标权衡，网上根据实际体验的排行榜也不胜计数，选用什么模型很多时候取决于你的任务内容和你的使用习惯，不必在模型性能上太过焦虑（除非差距真的很大，当我没说过）

其次，为什么是基于vscode插件的形式。首先就是适配vscode，这一优点已经足够让一个代码工作者选择插件了，尤其是在几天前vscode最好用的几个功能之一——copilot，不再接受学生认证薅羊毛，断绝了低价调用强大agent的路线，直接使用官方插件已然是最好的选择

此外，也有很多其他调用CLI的方式，比如说一些开源的编辑器甚至agent team app，有些功能独特值得一试，但是都是后话，作为独立的开发者，掌握尽可能原生的开发环境是很必要的，熟练使用vscode插件可以帮你应对大多数场景

## 上手操作部署cc

如果你已经是vscode熟手，并且对于cc/codex已经有基本的概念，就可以跟着下面的教程手把手在自己的vscode中部署强大的AI agent来解放生产力了

### 第一步：获取API key

所有的CLI都推荐使用API的形式而非订阅的形式来调用，这一点对于cc/codex这样的国外agent尤其重要，因为superwall，订阅会比较困难，而且在本地登录购买了订阅的账号更是相当困难，倘若你只在自己的本地设备上使用cc并且对于越过superwall有充足的自信，随便你

但是对于多数应用场景，包括开发环境使用学校服务器、云平台这样的远程设备，API key是最容易的途径

不过，并非是官方的API key，昂贵且有连接问题。事实上，我们在国内一般通过第三方中转来接触到可用的API，当然，由于承包给了第三方，不同商家的定价、服务自然有区别，或许其中有的商家可能偷偷夸大了实际的token用量或者在高峰期限流。笔者并没有货比三家，而是一直在使用一个相当稳定的API平台：LuckyAPI，官网网址：[LuckyAPI](https://luckyapi.chat/)

注意，这并非广告，笔者未从这一推荐中获取任何利润！不过还是推荐大家如果有购买需求可以通过我的邀请码：https://luckyapi.chat/register?aff=e2hW 注册登录，就当给笔者辛苦码字的报酬（笔者撰写这篇文章未借助任何AI工具）

官网会提供详细的充值、创建API key、使用API key的帮助，不过由于实现方式略有不同，我仍会给出详细的分布操作

假定你已经往账号中充过💴，就可以"创建令牌"也就是API key，推荐设置如下，可以通过这一令牌自由使用平台支持的所有模型（当然，越贵的模型扣费越快），并且会根据流量自动调整

![lucky创建apikey](/Dr_xiaoma-Blog/images/claude-code-vscode-setup/lucky创建apikey.png)

创建完成后，你就可以拿到一份密钥，形式为`sk-xxxxxx`，复制这一密钥保存到你自己知道的一个私密位置，不要遗忘，不要随意分享给其他人，这是从你账号上扣费的唯一凭证

### 第二步：安装cc插件

在vscode插件商场搜索"Claude"，一定能在第一个位置看到 Anthropic 官方认证的插件，直接下载安装即可，无需任何多余操作，这就是适配

![cc插件](/Dr_xiaoma-Blog/images/claude-code-vscode-setup/cc插件.png)

安装完毕后会在左侧边栏和右上角出现cc的专属logo，说明插件已启用，但先不要点开启动，否则你会发现cc要求你登录，而显然身在国内的我们无法搞到这样一个账号。我们通过配置文件绕开这一步并且接上我们购买的国内API

### 第三步：修改cc配置文件

在安装完插件后，你的工作区根目录下会多出一个名为`.claude`的目录，点开之后你会发现里面只有寥寥几个目录，别担心，随着日后的使用，cc会日渐完善

首先，你需要在`.claude`目录下创建一个json文件，名字严格设置为`settings.json`，这是cc官方的配置文件命名，直接决定了cc的核心配置。这也能体现出使用编辑器CLI而非网页版的好处——你可以通过修改配置文件方便地控制你的agent

然后将以下内容复制到其中

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://cn.luckyapi.chat",
    "ANTHROPIC_AUTH_TOKEN": "sk-你的API密钥"
  },
  "includeCoAuthoredBy": false
}
```

如果不出意外，再通过快捷键呼出右边栏的cc，你会发现登录界面消失了，直接展开了对话框

当然，此时推荐你选定内核模型，通过点击功能栏（对话框下面那个方框加/的按钮），可以看到switch model选项，点击后选择claude-opus-4-6

初次登录，你可能看不到我下面的这些模型，可以暂时选择opus 4.7，后续我们可以通过配置文件自由切换

选择好模型后，再点击功能栏，确认开启了thinking，effort推荐选"High"，再高的等级烧token相当快，非相当重要且困难的项目不推荐

![modelchoose](/Dr_xiaoma-Blog/images/claude-code-vscode-setup/modelchoose.png)

看到这个回复，你可以舒一口气了，你已经跨越了80%的困难，成功部署了可以调用的cc agent

但是要发挥cc的全部威力，你可能还需要额外一些步骤，组装适配你任务的Harness

### 第四步：完善CLAUDE.md（可选）

CLAUDE.md是cc执行对话时每次都会调用的文件，一般放置核心的工作规范、任务边界、角色职责等不容有失的内容，由于每次都会调用，所以不会遗忘或产生幻觉

首先，无论在哪个session（即单个对话框）、哪个项目目录，cc都会优先调用`.claude/CLAUDE.md`，所以这个md文件写最基本的逻辑、最普遍的规范，这里笔者推荐github开源项目 https://github.com/forrestchang/andrej-karpathy-skills 的md，部分内容如下：

> # CLAUDE.md
>
> Behavioral guidelines to reduce common LLM coding mistakes. Merge with project-specific instructions as needed.
>
> **Tradeoff:** These guidelines bias toward caution over speed. For trivial tasks, use judgment.
>
> ## 1. Think Before Coding
>
> **Don't assume. Don't hide confusion. Surface tradeoffs.**
>
> Before implementing:
> - State your assumptions explicitly. If uncertain, ask.
> - If multiple interpretations exist, present them - don't pick silently.
> - If a simpler approach exists, say so. Push back when warranted.
> - If something is unclear, stop. Name what's confusing. Ask.
>
> ## 2. Simplicity First
>
> **Minimum code that solves the problem. Nothing speculative.**
>
> - No features beyond what was asked.
> - No abstractions for single-use code.
> - No "flexibility" or "configurability" that wasn't requested.
> - No error handling for impossible scenarios.
> - If you write 200 lines and it could be 50, rewrite it.
>
> Ask yourself: "Would a senior engineer say this is overcomplicated?" If yes, simplify.
>
> ... ...

然后，在你的项目目录下，cc还会在工作时调用项目根目录下的`CLAUDE.md`，这个文件仅在这个项目中发挥作用，一般针对项目内容进行针对性地编写，这是人类工程师最重要的工作之一，内容可以涉及角色职责、任务边界、项目结构、交付标准等等

后面我可能会交出焚绝，展示我常用的角色文档，敬请期待

### 第五步：安装plugins/skills（可选）

skill赋予cc特化的能力，通过提示词或者后训练，能让cc调用一些外部接口功能或者更专注更高效地处理一些具体的问题，将诸多skill结合起来，就构成了一个强大的外接工具，称为plugin

> 实际上，skills/plugin比我的描述要复杂很多，好的skill可以让你的cc做到一些难以想象的事，可以通过 [The Agent Skills Directory](https://skills.sh/) 查询，如果你在Openclaw爆火时期养过龙虾，那么对这一套扩展agent功能的方案应该不陌生

在cc对话框中键入/plugin，会看到`manage plugins`这一功能，点进去，你会发现弹出的窗口一个插件都没有！

不要急，因为你没有添加可以找到插件的路径，在右侧的添加市场功能中粘贴Anthropic官方的插件库：https://github.com/anthropics/claude-plugins-official.git

点击Add后应该能看到添加成功：

![plugins](/Dr_xiaoma-Blog/images/claude-code-vscode-setup/plugins.png)

在点击plugins，就能看到诸多官方插件供你挑选了，这些插件经官方重重审核，可信度较高，是我推荐的下载方式

当然，如果你有意试用最新的plugin/skill，可以在社区自行搜索，直接将想要下载的文件目录塞到`.claude`目录下的对应位置就行，和官方下载方式本质一样

笔者推荐以下几个plugins：

![skills](/Dr_xiaoma-Blog/images/claude-code-vscode-setup/skills.png)

> context7增强cc的上下文管理
>
> frontend-design增强cc的前端制作能力，若无相关需求不用下载
>
> skill-creator可以订制skill，你有功能需要频繁使用时可以让cc制作相应skill永久记忆

> superpowers强推，大规模任务必备，指导cc主动询问需求、制定计划、前期调研、开展实验、编写代码并审查、返工...成为一位专业的工程师，代价是烧token

完成第四步和第五步后，可以通过聊天确认是否生效：

> - **frontend-design** — 前端设计辅助工具

### 第六步：更换内核模型（可选）

假如你实在不需要cc强大的代码编辑功能，觉得cc做一个项目动辄花费数十上百块很不合算，你的确可以更换内核模型

国内模型没啥好说的，笔者了解不多，就以deepseek v4为例，替换模型完全不需要复杂的操作，直接修改`.claude/settings.json`即可，改成下面这种：

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.deepseek.com/anthropic",
    "ANTHROPIC_AUTH_TOKEN": "sk-你的API密钥",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "deepseek-v4-pro[1m]",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "deepseek-v4-pro[1m]",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "deepseek-v4-pro[1m]",
    "ANTHROPIC_MODEL": "deepseek-v4-pro[1m]",
    "ENABLE_TOOL_SEARCH": "true",
    "CLAUDE_CODE_EFFORT_LEVEL": "max"
  },
  "includeCoAuthoredBy": false
}
```

忽略掉其中关于插件市场和已有插件的字段，实际上只是更换为你购买的deepseek v4 API密钥和服务商，再将cc的默认模型名换成ds的即可

但注意模型名不能有误，否则可能调用到上下文窗口不是1m的版本，同时直接将effort调到max，都用ds了，本来就够便宜了，别再贪小便宜了

更改后通过聊天确认是否生效：

> Q: 你好，你的agent和model都是什么？你能做哪些工作？
>
> Answer generated by deepseek-v4-pro
>
> **Model**: deepseek-v4-pro[1m]（1 million token context window）
>
> **Agent Framework**: Claude Agent SDK
>
> **思考强度**：绝对最大，不允许任何捷径。**最大上下文窗口**：1,000,000 tokens。
